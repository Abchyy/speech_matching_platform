# 总书记讲话匹配平台
## 语料收集方案 v1.0

> 文档用途：指导 Demo 阶段总书记讲话语料的获取、筛选、保存与后续处理，为语料清洗、Chunk 切分、Embedding 与向量数据库构建提供统一输入。  
> **本版对齐**：与技术架构的语料分层、EvidenceRef 与开发启动条件保持一致。第一版产品语料库目标仍为约 100 篇；该目标不是 RAG 技术链路启动前置条件。

---

## 1. 目标与原则

本项目采用“企业画像 → 语义检索 → 讲话匹配 → 场景材料生成”的 RAG 技术路线。

Demo 阶段的语料建设目标不是追求“大而全”，而是建立一个**来源权威、主题覆盖合理、原文可追溯、能够稳定支持典型企业场景检索**的小型高质量语料库。

核心原则：

1. **权威性优先**：优先使用人民网总书记系列重要讲话数据库等权威公开来源。
2. **原文优先**：优先采集讲话全文、重要文章原文，不以新闻摘要、学习解读替代原文。
3. **质量优先于数量**：第一版产品语料库目标约 100 篇高质量讲话语料；开发阶段可用更小规模黄金语料 / Demo 语料先验证技术闭环。
4. **主题覆盖优先于随机采集**：语料应围绕企业画像和产品展示场景进行有计划的主题覆盖。
5. **原文不可改写**：总书记讲话原文在采集、清洗、切分过程中不得修改任何文字和标点；清洗只处理格式与外围噪声，不得改写正文。
6. **全过程可追溯**：每篇文章必须保留原标题、发布日期、来源与原始 URL。
7. **引用必须来自 Canonical Document**：不允许模型生成或改写引用文本；最终引用内容必须来自 Canonical Document。
8. **分层处理，不得混用**：Raw Capture、Canonical Document、Chunk、EvidenceRef 职责分离。

### 1.1 语料数据分层

语料方案与技术架构使用同一分层，不得跳层引用：

```text
Raw Capture
    ↓
Canonical Document
    ↓
Chunk
    ↓
EvidenceRef
```

- **Raw Capture**：原始采集结果，保留抓取现场（含网页噪声、原始 Markdown、采集 metadata）。不得直接作为引用源。
- **Canonical Document**：经过清洗与确认后的权威正文。其中总书记讲话原文不可修改。
- **Chunk**：从 Canonical Document 按字符原样切出的检索文本单元，是检索与用户确认的最小证据单位。
- **EvidenceRef**：用户确认和引用追溯单位。MVP 中指向整个 Chunk，偏移基于该 Chunk 的 `text`。

Chunk 与 EvidenceRef 都是派生数据，只能切片或引用 Canonical 正文，不得反向改写原文。

## 2. Demo 阶段目标规模

第一版产品语料库目标：

```text
约100篇总书记讲话语料
```

该规模是**产品能力建设目标**，用于主题覆盖和可展示的检索质量，**不是 RAG 技术链路启动的前置条件**。

不得将工程约束表述为：必须完成 100 篇后才能进入 RAG 开发。

### 2.1 产品语料库规模（约 100 篇）

预计规模：

| 项目 | 建议规模 |
|---|---:|
| 原始讲话文章 | 约 100 篇 |
| 清洗后讲话文章（Canonical Document） | 约 100 篇 |
| Chunk 数量 | 约 1,000–3,000 个 |
| 向量记录 | 约 1,000–3,000 条 |
| Demo 验证企业案例 | 约 10 个 |

该规模主要用于验证：

- 企业画像是否能够召回正确主题；
- Top-K 讲话匹配是否具有明显相关性；
- 后续生成材料时是否能够引用准确、可追溯的讲话原文；
- 整个产品流程是否具备可展示的实际价值。

如果首批语料表现良好，可继续扩展至 200–300 篇。

### 2.2 开发阶段小规模语料

开发阶段允许先使用：

- 小规模黄金语料；
- Demo 测试语料；

提前验证：

- 数据处理；
- Chunk；
- Embedding；
- 检索；
- Evidence；
- 生成闭环。

小规模语料同样必须遵守原文不可改写、分层处理和 EvidenceRef 追溯要求。约 100 篇完整语料在技术闭环跑通后继续建设，不阻塞 Pipeline 启动。

## 3. 首选语料来源

### 3.1 核心来源

首批语料优先来源于：

**人民网总书记系列重要讲话数据库**

`https://jhsjk.people.cn/result?keywords=%E7%A7%91%E6%8A%80&isFuzzy=1`

后续也可以扩展：

- 求是网；
- 新华社；
- 其他中央权威媒体或官方转载页面。

### 3.2 来源优先级

建议优先级：

1. 权威数据库中的讲话原文；
2. 新华社、人民日报、求是网正式发布的原文；
3. 中央或政府官方网站完整转载；
4. 其他可靠转载来源。

不建议作为核心语料：

- 新闻摘要；
- 评论文章；
- 学习心得；
- 二次解读；
- 自媒体整理；
- 来源不明的 TXT / Markdown 合集。

## 6. 文章质量要求

一篇文章进入核心语料库前，至少应满足以下要求。

### 6.1 必须满足

- 来源可追溯；
- 有明确标题；
- 有原始页面 URL；
- 原文主体完整；
- 正文中包含总书记原始讲话或署名文章内容；
- 与目标主题具有实际语义相关性。

### 6.2 优先保留

优先选择：

- 讲话全文；
- 主旨演讲；
- 重要会议讲话；
- 正式致辞；
- 署名文章；
- 对企业、经济、科技、产业、文化、人才等主题具有较高信息密度的文本。

### 6.3 降低优先级或排除

以下内容原则上不进入核心语料集，除非确有特殊价值：

- 单纯活动报道；
- 会见新闻；
- 行程新闻；
- 贺信、贺电；
- 新闻摘要；
- “各地学习贯彻”类报道；
- 二次评论或理论解读；
- 大量内容高度重复的转载。

## 7. 自动化采集方案

语料采集工作由 Cursor Coding Agent 在正式产品仓库内完成。

整体流程：

```text
人民网讲话数据库
        ↓
关键词搜索
        ↓
搜索结果解析
        ↓
候选文章收集
        ↓
URL / 标题去重
        ↓
详情页抓取
        ↓
正文解析
        ↓
Markdown 原始语料（Raw Capture）
        ↓
metadata 索引
```

Crawler 的输出停在 Raw Capture。Canonical Document、Chunk、EvidenceRef 属于后续处理，不由采集模块完成。

### 7.1 Crawler 的职责

Crawler 负责：

- 根据配置关键词获取搜索结果；
- 获取文章详情页面；
- 解析标题、日期、来源、URL 和正文；
- 根据 URL 或稳定标识去重；
- 将原始文章保存为 Markdown；
- 生成统一 metadata；
- 对失败页面记录日志；
- 支持重复执行而不重复抓取。

Crawler **不负责**：

- 改写讲话原文；
- 自动总结讲话；
- 润色或纠正讲话文本；
- 生成或改写引用文本；
- 构建 Embedding；
- 构建向量数据库；
- 构造 EvidenceRef。

## 8. 原始 Markdown 格式（Raw Capture）

每篇讲话保存为独立 Markdown 文件，作为 Raw Capture 落盘。该层允许保留抓取现场噪声，但正文仍不得被模型改写。

建议格式：

```markdown
---
id: speech_001
title: 文章标题
date: YYYY-MM-DD
source: 人民网
url: 原始URL
retrieval_keywords:
  - 科技创新
  - 高质量发展
---

# 文章标题

原始正文……
```

其中：

- `retrieval_keywords` 记录该文章通过哪些搜索关键词被发现；
- 正文必须保留抓取到的原始文本；
- 同一文章如果由多个关键词命中，只保留一个文件，并合并关键词信息。
- Raw Capture 不得直接作为 Canonical Quote 或生成引用源；引用必须来自后续确认的 Canonical Document。

speech_matching_platform/

├── docs/

│
├── corpus/
│   ├── raw/

│   │   └── ...
│   │

│   └── crawler/
│

│
├── README.md

其中：

EvidenceRef 是检索、用户确认与生成引用时的运行时协议，不单独建设一类语料目录或新的数据系统。

## 10. 后续语料处理流程

采集完成后，语料按架构分层依次进入：

```text
Raw Capture
    ↓
Canonical Document
    ↓
Chunk
    ↓
Embedding / 本地向量数据库
    ↓
语义检索
    ↓
EvidenceRef（用户确认整个 Chunk）
    ↓
生成闭环（程序按 EvidenceRef 回填原文）
```

### 10.1 基础清洗（Raw Capture → Canonical Document）

清洗过程**只能处理格式问题与外围噪声**，不得改写总书记讲话原文。

允许处理：

- HTML 残留；
- 页面导航；
- 分享按钮；
- 编辑信息；
- 推荐文章；
- 无关网页元素；
- 异常空行；
- Markdown 格式错误。

禁止处理：

- 改写原文；
- 自动纠错；
- 替换原文措辞；
- 修改原文标点；
- 用摘要代替正文；
- 用模型生成或“复述”后冒充原文。

进入 Canonical Document 后，总书记讲话原文不可修改。最终引用内容必须来自 Canonical Document，不允许模型生成或改写引用文本。

### 10.2 Chunk 切分（Canonical Document → Chunk）

后续切分应尽可能尊重自然段落和语义边界。Chunk 文本必须是 Canonical Document 的原样子串，不得改写。

初步可参考：

- 单 Chunk 约 500–800 个中文字符；
- 适度重叠约 100–150 个字符。

具体长度与 overlap 参数应在检索实验后确定，不在本语料收集阶段冻结。

### 10.3 Chunk 级 Evidence（MVP 冻结）

当前 MVP 冻结如下方案，不引入更复杂引用系统：

- 用户确认粒度为 **整个 Chunk**；
- **不支持** Chunk 内 Span 选择；
- EvidenceRef 的 `startIndex` / `endIndex` 基于该 Chunk 的 `text`；
- 确认整个 Chunk 时，`startIndex = 0` 且 `endIndex = chunk.text.length`。

EvidenceRef 至少包含：

```text
speechId
chunkId
startIndex
endIndex
```

检索结果以 Chunk 为最小证据单位。用户确认的是 Evidence，而不是仅仅 Speech。后续生成必须基于已确认 EvidenceRef；引用文本由程序从 Canonical Chunk 回填，不得由模型自由生成。

## 11. 采集完成后的人工验收

产品语料库扩展至约 100 篇后，应进行一次轻量人工验收。开发阶段的小规模黄金/Demo 语料也应做同等原则的抽查，但**不必等到 100 篇完成才开始 RAG 开发**。

重点检查：

1. 是否存在抓取失败或正文为空；
2. 是否混入大量新闻报道而非讲话原文；
3. 是否存在明显重复文章；
4. 十类主题是否基本覆盖；
5. 是否存在某个关键词大量占据语料库；
6. 标题、日期、URL 是否完整；
7. 原文是否出现乱码、截断或网页噪声；
8. 是否存在需要从核心语料库剔除的低价值文章。

无需逐篇进行深度人工标注。

7. 教育科技企业；
8. 国有企业；
9. 外贸企业；
10. 综合型大型企业。

每个案例至少人工判断：

- Top-3 是否主题相关；
- Top-5 是否存在明显错误召回；
- 返回讲话是否能够支持后续材料生成；
- 引用是否能够按 EvidenceRef 追溯到 Canonical Document 原文。

首批产品语料库是否需要扩容，应以该验证结果为依据，而不是单纯以文章数量判断。开发阶段可先用小规模语料完成上述验证。

## 13. Demo 阶段成功标准

### 13.1 技术链路启动标准

满足以下条件即可启动数据处理、Chunk、Embedding、检索、Evidence 与生成闭环验证，**不以约 100 篇为前置条件**：

- 已有可读取的 Raw Capture（可为小规模黄金语料或 Demo 语料）；
- metadata 可以被程序统一读取；
- 原文保持完整且未被改写；
- 能够从 Canonical Document 派生 Chunk，并构造 Chunk 级 EvidenceRef。

### 13.2 第一版产品语料库成功标准

第一版产品语料库目标约 100 篇总书记讲话语料。达到以下条件视为产品能力建设达标，而不是 RAG 开发开门条件：

- 已获取约 100 篇权威讲话语料；
- 十类核心主题具备基本覆盖；
- 每篇文章均具有标题、来源、URL 与正文；
- 原文保持完整且未被改写；
- 重复和明显低质量文本已基本排除；
- 原始语料以 Markdown 形式纳入项目目录（Raw Capture）；
- metadata 可以被程序统一读取；
- 10 个典型企业场景具有可用于检索验证的语料覆盖。

## 14. 当前阶段边界

本方案当前只冻结以下内容：

- 第一版产品语料库目标约 100 篇（产品能力目标，不是 RAG 启动前置条件）；
- 优先使用人民网总书记系列重要讲话数据库；
- 按企业相关主题进行结构化覆盖；
- 原始语料保存为 Markdown（Raw Capture）；
- 语料分层为 Raw Capture → Canonical Document → Chunk → EvidenceRef；
- 总书记讲话原文不可修改；清洗只处理格式与外围噪声；
- 不允许模型生成或改写引用文本；最终引用必须来自 Canonical Document；
- MVP 用户确认粒度为整个 Chunk，不支持 Chunk 内 Span 选择；
- EvidenceRef 偏移基于 Chunk `text`；确认整个 Chunk 时为 `[0, chunk.text.length)`；
- 语料采集、清洗、Chunk、Embedding 分阶段进行；
- 语料采集模块纳入正式产品仓库。

以下内容暂不冻结，后续研发中应根据实际效果人工确认：

- 具体每个关键词最终抓取数量；
- 精确主题分类体系；
- metadata 最终字段；
- Chunk 精确长度与 overlap 参数；
- 自动主题标签策略；
- 是否扩展至人民网之外的其他来源；
- 最终语料规模。
