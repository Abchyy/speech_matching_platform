# 总书记讲话匹配平台
## 语料收集方案 v1.0

> 文档用途：指导 Demo 阶段总书记讲话语料的获取、筛选、保存与后续处理，为语料清洗、Chunk 切分、Embedding 与向量数据库构建提供统一输入。

---

## 1. 目标与原则

本项目采用“企业画像 → 语义检索 → 讲话匹配 → 场景材料生成”的 RAG 技术路线。

Demo 阶段的语料建设目标不是追求“大而全”，而是建立一个**来源权威、主题覆盖合理、原文可追溯、能够稳定支持典型企业场景检索**的小型高质量语料库。

核心原则：

1. **权威性优先**：优先使用人民网总书记系列重要讲话数据库等权威公开来源。
2. **原文优先**：优先采集讲话全文、重要文章原文，不以新闻摘要、学习解读替代原文。
3. **质量优先于数量**：Demo 阶段先确保约 100 篇高质量语料可用，再考虑扩容。
4. **主题覆盖优先于随机采集**：语料应围绕企业画像和产品展示场景进行有计划的主题覆盖。
5. **原文不可改写**：总书记讲话原文在采集、清洗、切分过程中不得修改任何文字和标点；仅允许清除网页外围噪声、补充结构化元数据。
6. **全过程可追溯**：每篇文章必须保留原标题、发布日期、来源与原始 URL。

## 2. Demo 阶段目标规模

第一阶段建议构建约 **100 篇讲话文章** 的黄金语料集。

预计规模：

| 项目 | 建议规模 |
|---|---:|
| 原始讲话文章 | 约 100 篇 |
| 清洗后讲话文章 | 约 100 篇 |
| Chunk 数量 | 约 1,000–3,000 个 |
| 向量记录 | 约 1,000–3,000 条 |
| Demo 验证企业案例 | 约 10 个 |

该规模主要用于验证：

- 企业画像是否能够召回正确主题；
- Top-K 讲话匹配是否具有明显相关性；
- 后续生成材料时是否能够引用准确、可追溯的讲话原文；
- 整个产品流程是否具备可展示的实际价值。

如果首批语料表现良好，可继续扩展至 200–300 篇。

## 3. 首选语料来源

### 3.1 核心来源

首批语料优先来源于：

**人民网总书记系列重要讲话数据库**

入口示例：

`https://jhsjk.people.cn/result?keywords=%E7%A7%91%E6%8A%80&isFuzzy=1`

后续也可以扩展：

- 求是网；
- 新华社；
- 其他中央权威媒体或官方转载页面。

### 3.2 来源优先级

建议优先级：

1. 权威数据库中的讲话原文；
2. 新华社、人民日报、求是网正式发布的原文；
3. 中央或政府官方网站完整转载；
4. 其他可靠转载来源。

不建议作为核心语料：

- 新闻摘要；
- 评论文章；
- 学习心得；
- 二次解读；
- 自媒体整理；
- 来源不明的 TXT / Markdown 合集。

## 6. 文章质量要求

一篇文章进入核心语料库前，至少应满足以下要求。

### 6.1 必须满足

- 来源可追溯；
- 有明确标题；
- 有原始页面 URL；
- 原文主体完整；
- 正文中包含总书记原始讲话或署名文章内容；
- 与目标主题具有实际语义相关性。

### 6.2 优先保留

优先选择：

- 讲话全文；
- 主旨演讲；
- 重要会议讲话；
- 正式致辞；
- 署名文章；
- 对企业、经济、科技、产业、文化、人才等主题具有较高信息密度的文本。

### 6.3 降低优先级或排除

以下内容原则上不进入核心语料集，除非确有特殊价值：

- 单纯活动报道；
- 会见新闻；
- 行程新闻；
- 贺信、贺电；
- 新闻摘要；
- “各地学习贯彻”类报道；
- 二次评论或理论解读；
- 大量内容高度重复的转载。

## 7. 自动化采集方案

语料采集工作由 Cursor Coding Agent 在正式产品仓库内完成。

整体流程：

```text
人民网讲话数据库
        ↓
关键词搜索
        ↓
搜索结果解析
        ↓
候选文章收集
        ↓
URL / 标题去重
        ↓
详情页抓取
        ↓
正文解析
        ↓
Markdown 原始语料
        ↓
metadata 索引
```

### 7.1 Crawler 的职责

Crawler 负责：

- 根据配置关键词获取搜索结果；
- 获取文章详情页面；
- 解析标题、日期、来源、URL 和正文；
- 根据 URL 或稳定标识去重；
- 将原始文章保存为 Markdown；
- 生成统一 metadata；
- 对失败页面记录日志；
- 支持重复执行而不重复抓取。

Crawler **不负责**：

- 改写讲话原文；
- 自动总结讲话；
- 润色或纠正讲话文本；
- 构建 Embedding；
- 构建向量数据库。

---

## 8. 原始 Markdown 格式

每篇讲话保存为独立 Markdown 文件。

建议格式：

```markdown
---
id: speech_001
title: 文章标题
date: YYYY-MM-DD
source: 人民网
url: 原始URL
retrieval_keywords:
  - 科技创新
  - 高质量发展
---

# 文章标题

原始正文……
```

其中：

- `retrieval_keywords` 记录该文章通过哪些搜索关键词被发现；
- 正文必须保留抓取到的原始文本；
- 同一文章如果由多个关键词命中，只保留一个文件，并合并关键词信息。

## 10. 后续语料处理流程

采集完成后，语料依次进入：

```text
Raw Corpus
    ↓
基础清洗
    ↓
结构化 Metadata
    ↓
Chunk 切分
    ↓
Embedding
    ↓
本地向量数据库
    ↓
语义检索
    ↓
LLM / Reranker
```

### 10.1 基础清洗

允许处理：

- HTML 残留；
- 页面导航；
- 分享按钮；
- 编辑信息；
- 推荐文章；
- 无关网页元素；
- 异常空行；
- Markdown 格式错误。

禁止处理：

- 改写原文；
- 自动纠错；
- 替换原文措辞；
- 修改原文标点；
- 用摘要代替正文。

### 10.2 Chunk 切分

后续切分应尽可能尊重自然段落和语义边界。

初步可参考：

- 单 Chunk 约 500–800 个中文字符；
-适度重叠约 100–150 个字符。

具体参数应在检索实验后确定，不在本语料收集阶段冻结。

## 11. 采集完成后的人工验收

自动抓取约 100 篇后，应进行一次轻量人工验收。

重点检查：

1. 是否存在抓取失败或正文为空；
2. 是否混入大量新闻报道而非讲话原文；
3. 是否存在明显重复文章；
4. 十类主题是否基本覆盖；
5. 是否存在某个关键词大量占据语料库；
6. 标题、日期、URL 是否完整；
7. 原文是否出现乱码、截断或网页噪声；
8. 是否存在需要从核心语料库剔除的低价值文章。

无需逐篇进行深度人工标注。

2. 新能源制造企业；
3. 传统制造业数字化转型企业；
4. 民营中小企业；
5. 农业科技企业；
6. 文旅企业；
7. 教育科技企业；
8. 国有企业；
9. 外贸企业；
10. 综合型大型企业。

每个案例至少人工判断：

- Top-3 是否主题相关；
- Top-5 是否存在明显错误召回；
- 返回讲话是否能够支持后续材料生成；
- 引用是否能够追溯到原文。

首批语料库是否需要扩容，应以该验证结果为依据，而不是单纯以文章数量判断。

## 13. Demo 阶段成功标准

语料建设阶段达到以下条件，即可进入后续 RAG 数据库构建：

- 已获取约 100 篇权威讲话语料；
- 十类核心主题具备基本覆盖；
- 每篇文章均具有标题、来源、URL 与正文；
- 原文保持完整且未被改写；
- 重复和明显低质量文本已基本排除；
- 原始语料以 Markdown 形式纳入项目目录；
- metadata 可以被程序统一读取；
- 10 个典型企业场景具有可用于检索验证的语料覆盖。
